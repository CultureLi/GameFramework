# 地图编辑器、地图数据与寻路导航系统

> 本文档整理当前已实现的地图编辑、地图数据导出、运行时流式加载、NavMesh 导航、寻路同步与关卡权限方案。
> 每个功能同时记录「需求」与「实现方式」，便于后续维护和扩展。

---

## 1. 范围与总体目标

### 1.1 目标

1. 在 Unity 编辑器中可视化摆放地图实体：建筑、装饰物、采集资源、障碍物。
2. 将摆放结果同时导出给客户端（ScriptableObject）和服务端（二进制）。
3. 客户端运行时按玩家/相机范围流式创建和销毁地图实体，避免整图常驻。
4. 服务端使用与客户端一致的 NavMesh 数据做权威寻路，客户端只做表现和本地预测。
5. 关卡建筑支持归属、通行申请、审批、移除通行权，服务端按玩家过滤导航多边形。
6. 装饰物不参与 NavMesh 烘焙，障碍物参与烘焙并形成阻挡。

### 1.2 客户端 / 服务端职责

| 端 | 职责 |
|---|---|
| Unity 编辑器 | 摆放实体、维护 InstanceId、导出客户端/服务端地图数据、整理场景资产、烘焙/导出 NavMesh |
| Unity 运行时 | 加载地图数据、四叉树管理、按相机投射框创建/销毁实体、本地预测移动、关卡 UI |
| C# 服务端 | 加载地图与导航数据、权威寻路、移动推进与位置同步、关卡归属与通行权限、按玩家过滤导航多边形 |

## 3. 配置表

### 3.1 使用到的表

| 表 | 用途 |
|---|---|
| `MapBuildingCfg` | 建筑配置；`Id`、`AssetId`、`Name`、`Type`、`Level` |
| `MapResourceCfg` | 采集资源配置；`Id`、`AssetId`、`Name`、`Type`、`Level` |
| `AssetPathCfg` | 资源路径表；装饰物、障碍物直接用它作为配置 Id |

### 3.2 皮肤/模型解析

- 建筑/资源：`MapBuildingCfg.AssetId` / `MapResourceCfg.AssetId` -> `AssetPathCfg.AssetPath`。
- 装饰物/障碍物：配置 Id 就是 `AssetPathCfg.Id`，直接取 `AssetPath`。
- 编辑器放置和运行时创建都通过 Addressables 实例化 prefab。

### 3.3 建筑类型历史值

`MapBuildingCfg.Type` 当前数据是 `1=关卡、2=普通建筑`，而 proto `BuildingType` 是 `Base=1、Gate=2`，数值相反。

`MapBuildingTypeHelper.IsGate` 同时参考：

1. 资源路径或名称是否像关卡（`Gate` / `关卡`）；
2. `Type == 1` 或 `Type == BuildingType.Gate`。

正式数据建议统一到 `BuildingType` 枚举后删掉路径兜底。

## 4. 场景节点与实体数据

### 4.1 作者场景节点层级

```
DataEditor                     // MapAuthoringRoot 标记，运行时整体隐藏
├─ Building                     // 建筑（含关卡建筑）
├─ Decorate                     // 装饰物
├─ Resource                     // 采集资源
├─ Obstacle                     // 障碍物
└─ Walls                        // 地形/围墙生成器创建的墙体（导出时并入 Obstacle）
```

- `DataEditor` 必须是场景根节点。
- 旧布局 `Scene/DataRoot`、`Scene/DataEditor` 会在 `MapEditorUtils.EnsureHierarchy` 中自动迁移。
- 运行时 `MapDataMgr` 找到带 `MapAuthoringRoot` 的根节点并整体隐藏，避免与流式创建的对象重复。

### 4.2 MapEntityInfo

每个可直接导出的实体挂 `MapEntityInfo`：

| 字段 | 说明 |
|---|---|
| `Category` | `Building / Decorate / Resource / Obstacle` |
| `ConfigId` | 建筑/资源配置 Id；装饰物/障碍物为 `AssetPathCfg.Id` |
| `InstanceId` | 实例唯一 Id；导出地图数据、服务端关卡权限都使用它 |
| `AssetId` | 建筑/资源为 `AssetPathCfg.Id`；装饰物/障碍物与 `ConfigId` 相同 |

### 4.3 InstanceId 策略

- 放置时生成一次：`Guid.NewGuid().ToString("N")`。
- 导出时如果为空会补生成，并写回组件、标记场景 Dirty。
- 导出时用 `HashSet` 检查重复，重复会直接报错并跳过该条。
- 编辑器提供「补全/修复 UID」按钮，修复空 Id 和复制导致的重复 Id。
- 多人同时编辑时，天然 GUID 冲突概率可忽略；但同一场景文件仍应避免多人同时保存（Unity 场景合并会丢数据）。正式多人协作建议把地图实体拆成按人/按区域的数据文件，或由服务端统一分配 InstanceId。

### 4.4 尺寸与旋转

- `Size`：取对象所有 `Collider`（没有则 `Renderer`）的世界包围盒 XZ。
- `RotationY`：`Mathf.Repeat(eulerAngles.y, 360)`。
- 运行时按 `Size + RotationY` 还原：见 6.4。

## 5. 地图编辑器

### 5.1 界面功能

`Tools/Map Editor` 打开窗口，当前包含：

1. **类型下拉框**：建筑物、装饰物、采集资源、障碍物。
   - 使用下拉而不是横向页签，方便后续继续增加类型。
2. **搜索框**：按名称、Id、资源路径过滤。
3. **实体列表**：点击选中并进入放置模式。
4. **放置设置**：
   - 放置模式开关；
   - Grid 吸附开关与格子大小；
   - 已放置对象移动时吸附。
5. **导出设置**：模块多选（Building / Decorate / Resource / Obstacle）与 All。
6. **导出按钮**：导出客户端数据、导出服务端数据。
7. **场景资产整理**：按当前打开场景推导目录，一键整理。
8. **NavMesh**：烘焙当前场景、导出 `.rnav` 到服务端目录。
9. **辅助按钮**：重新读取配置、创建/定位节点、补全/修复 UID。

### 5.2 放置流程

1. 选中条目后，Scene 视图出现预览对象（禁用 Behaviour 和 Collider，避免触发逻辑）。
2. 鼠标射线打到地面（优先物理碰撞，失败则用地面平面兜底）。
3. Grid 模式吸附到格子中心。
4. 左键放置：
   - `PrefabUtility.InstantiatePrefab` 到对应分类根节点；
   - 挂/更新 `MapEntityInfo`，写入 `Category / ConfigId / AssetId`；
   - 生成 `InstanceId`；
   - 装饰物自动挂 `NavMeshModifier` 并勾选 `Ignore From Build`；
   - 障碍物不挂 `NavMeshModifier`。
5. Esc 退出放置模式。

> 当前已移除 Grid 原点和「旋转 90°」按钮；放置时旋转为 `identity`，需要旋转时直接在 Scene 里调整。

### 5.3 装饰物 vs 障碍物

| 类型 | 配置来源 | NavMeshModifier | 对 NavMesh 的影响 |
|---|---|---|---|
| 装饰物 | `AssetPathCfg` | 挂载并勾选 `Ignore From Build` | 不参与烘焙，不阻挡 |
| 障碍物 | `AssetPathCfg` | 不挂载 | 参与烘焙，形成阻挡 |
| 建筑 | `MapBuildingCfg` | 建议勾选 `Ignore From Build` | 不参与烘焙 |
| 采集资源 | `MapResourceCfg` | 建议勾选 `Ignore From Build` | 不参与烘焙 |

实现补充：

- 装饰物除了放置时挂组件，导出时也会兜底检查并补挂（`MapDataExporter.EnsureIgnoreFromBuildModifier`），手动拖入或由其他工具创建的对象不会漏。
- 建筑/采集资源目前由地形/围墙生成器统一补挂 `Ignore From Build`；如果要完全保证，可以后续把同样的兜底逻辑扩展到这两类。
- `Walls` 下的墙体归类为障碍物（`AssetPathCfg 301 / Wall_1.prefab`），必须参与烘焙。

### 5.4 节点创建与迁移

`MapEditorUtils.EnsureHierarchy(true)`：

1. 找到或创建场景根节点 `DataEditor`；
2. 挂 `MapAuthoringRoot`；
3. 把旧布局里的分类节点迁移到 `DataEditor` 下；
4. 确保 `Building / Decorate / Resource / Obstacle` 四个分类根存在；
5. 删除空的旧 `Scene` 根节点。

### 5.5 导出

#### 5.5.1 导出要求

- 支持多选模块，`All` 等价于四个模块全选。
- 客户端和服务端可以分开导出。
- 客户端导出 ScriptableObject + 资源 Addressables 注册。
- 服务端导出二进制文件，不依赖客户端 prefab 是否存在。
- 导出路径按地图名定位：`Assets/BundleRes/MapData/<MapName>/`。

#### 5.5.2 地图名

`MapEditorUtils.GetMapName()`：

1. 优先取 Main 场景中 `WorldChunkStreaming.sceneName`（通常是 `OpenWorld`）；
2. 否则取当前打开场景名；
3. 非法文件名字符会替换为 `_`。

这样作者场景和运行时读写同一个地图数据目录。

#### 5.5.3 导出文件

| 模块 | 客户端 | 服务端 |
|---|---|---|
| Building | `BuildingData.asset` | `BuildingData.bytes` |
| Decorate | `DecorateData.asset` | `DecorateData.bytes` |
| Resource | `ResourceData.asset` | `ResourceData.bytes` |
| Obstacle | `ObstacleData.asset` | `ObstacleData.bytes` |

- `Walls` 节点下的墙体在勾选 **Obstacle** 模块时并入 `ObstacleData`。
- 客户端 prefab 注册到 Addressables 组 `Prefab`，SO 注册到 `CommonSOData`。
- 服务端二进制不进 Addressables。

#### 5.5.4 导出条目结构

`MapItemData`：

```csharp
int Id;                 // 建筑/资源配置 Id，或 AssetPathCfg.Id
string InstanceId;      // 实例唯一 Id
Vector2 Pos;            // 世界 XZ
Vector2 Size;           // 世界包围盒 XZ
float RotationY;        // 绕 Y 旋转
```

#### 5.5.5 二进制格式 MapDataBinary v2

小端：

```
uint32 magic      = 'MAP1'
int32  version    = 2
int32  count
count × {
    string instanceId,
    int32  id,
    float  posX, posZ,
    float  sizeX, sizeZ,
    float  rotationY
}
```

- 客户端导出 SO，服务端直接读取同一结构。
- 服务端项目链接 `MapDataBinary.cs`，不引用 UnityEngine。
- 当前只支持 v2，版本不一致会报错。

### 5.6 场景资产整理（MapEditor 集成）

#### 5.6.1 需求

把 TerrainToMesh 导出的地形资产从场景目录拆分到 BundleRes 下，便于按文件夹配 Addressables。入口不再要求先在 Project 窗口选中文件夹，而是按**当前打开的场景**自动推导。

#### 5.6.2 目录推导

以 `Assets/NoBundleRes/Scene/OpenWorld/OpenWorld.unity` 为例：

| 项 | 路径 |
|---|---|
| 场景目录 | `Assets/NoBundleRes/Scene/OpenWorld` |
| 场景名 | `OpenWorld` |
| 源目录 | `.../OpenWorld/OpenWorldTerrainData` |
| 源预制体 | `.../OpenWorld/OpenWorldTerrainData/OpenWorldTerrainData.prefab` |
| 地块根 | `Assets/BundleRes/SceneChunk/OpenWorld` |
| 贴图根 | `Assets/BundleRes/Texture/Scene/OpenWorld` |
| 材质根 | `Assets/BundleRes/Material/Scene/OpenWorld` |

#### 5.6.3 处理流程

1. 只读校验源目录、主预制体、地块节点，全部通过后才允许执行。
2. 确认弹窗列出将被清空的三个目标目录。
3. 创建/清空 `SceneChunk/<SceneName>`。
4. 遍历源预制体，把每个形如 `<前缀> x(i) y(j)` 的节点单独存为 prefab：
   `SceneChunk/<SceneName>/<ChunkName>/<ChunkName>.prefab`。
5. 把对应 `<ChunkName> Mesh.asset` 移动到同一个子文件夹。
6. 清空并重建贴图目录，移动源目录贴图。
7. 清空并重建材质目录，移动源目录材质。
8. 移动全部使用 `AssetDatabase.MoveAsset`，GUID/localId 不变，引用不断。
9. 报告缺失 Mesh 和未认领资源。

#### 5.6.4 入口

- `Assets/整理场景资产` 右键菜单：对选中的场景文件夹执行，行为保持兼容。
- MapEditor 窗口「整理当前场景资产」：按当前打开场景推导目录并执行。

### 5.7 NavMesh 烘焙与导出（MapEditor 集成）

#### 5.7.1 烘焙

- 找到场景中的 `NavMeshSurface`；没有则新建。
- 统一参数：
  - 位置/旋转归零；
  - `agentTypeID = 0`；
  - `collectObjects = All`；
  - `useGeometry = PhysicsColliders`；
  - `layerMask = ~0`；
  - `ignoreNavMeshAgent = true`；
  - `ignoreNavMeshObstacle = true`。
- 烘焙前临时禁用所有 `LevelGate` 的 `blockingCollider` / `NavMeshObstacle`，保证关卡门洞在静态导航网格里是通的；烘焙后恢复。
- 完成后标记 Surface / NavMeshData / 场景 Dirty 并保存资产。

#### 5.7.2 导出 .rnav

- 菜单 `Tools/RecastNavigationServer/Export NavMesh`：另存为。
- MapEditor 窗口「导出 NavMesh」：直接覆盖 `Server/NavData/navmesh.rnav`。
- `GameServer.csproj` 通过 `<None Include="..\NavData\navmesh.rnav" Link="NavData\navmesh.rnav" ...>` 把这份文件链接进构建输出；`publish/server/NavData/` 跟随发布。
- 导出后需要重启 GameServer 才会加载新数据。

## 6. 运行时地图数据与流式加载

### 6.1 加载入口

`MapDataMgr.Initialize()`：

1. 隐藏 `MapAuthoringRoot` 根节点；
2. 找 `WorldChunkStreaming`，取 `sceneName`（没有则当前场景名）；
3. 通过 Addressables 并行加载四个模块：
   - `BuildingData`
   - `DecorateData`
   - `ResourceData`
   - `ObstacleData`
4. 缺失模块只打印日志并跳过（支持按模块导出）；
5. 全部结束后创建 `MapDataStreaming` 并传入四个数据对象。

### 6.2 流式加载

`MapDataStreaming`：

- 把所有模块合并为 `List<MapRuntimeItem>`。
- 用 NativeTrees `NativeQuadtree<int>` 建立 XZ 空间索引（`Allocator.Persistent`）。
- 每 `refreshInterval`（默认 0.25s）取一次相机地面投射框：
  - 优先 `WorldChunkStreaming.TryGetCameraFootprintRect`；
  - 兜底 `WorldCameraController.TryGetFootprintRect`。
- 用 `RangeAABB` 查询框内实体，创建尚未加载的对象；离开框的对象释放。
- 必须等 `WorldChunkStreaming.LoadedChunkCount > 0` 后才开始创建实体，保证射线能打到地形。
- 相机自由拖拽，不跟随玩家；流式范围以相机投射框为准。

### 6.3 实例化与贴地

1. Addressables 异步实例化 prefab。
2. 异步回调期间重新检查投射框，避免相机已经移开还创建。
3. 挂到 `MapEntities` 根节点下。
4. `ApplySizeScale`：根据导出 `Size` 和 `RotationY` 反推 prefab 缩放：
   - 只在旋转接近 0/90/180/270（±5°）时缩放；
   - 0/180：本地 X 对应世界 X，本地 Z 对应世界 Z；
   - 90/270：本地 X 对应世界 Z，本地 Z 对应世界 X；
   - 其他角度保持 prefab 默认缩放（AABB 已混入旋转投影，无法反推）。
5. `GetPrefabGroundOffset`：用 Collider/Renderer 的最低点计算 pivot 偏移，保证中心 pivot 的墙体也能底部贴地。
6. 位置：`(Pos.x, 地形射线高度 + offset, Pos.y)`。
7. 关卡建筑额外挂 `GateBuilding`，写入 `InstanceId / ConfigId`，并禁用 prefab 上的全局 `LevelGate` / 障碍，因为建筑关卡通行由服务端按玩家计算。

### 6.4 生命周期

- `OnDestroy` 释放 NativeQuadtree / NativeList。
- 框架关闭时直接清空引用；正常销毁时逐个 `ReleaseInstance`。

## 7. 导航数据与寻路

### 7.1 导航数据生产

1. 场景里用 `NavMeshSurface` 烘焙。
2. 关卡门在烘焙时临时打开，保证门洞在静态网格里可通行。
3. `NavMeshExporter` 调用 `NavMesh.CalculateTriangulation()` 导出当前已烘焙的 NavMesh。
4. 同时收集：
   - `NavMeshLink`；
   - `LevelGate`（全局动态门）。
5. 写入 `.rnav`。

### 7.2 .rnav v2 格式

```
char[4] magic = "RNAV"
uint32  version = 2

float agentHeight
float agentRadius
float agentClimb
float cellSize
float cellHeight

int32 vertexCount
vertexCount × (float x, float y, float z)

int32 triangleCount
triangleCount × 3 × int32 indices

triangleCount × uint8 area

int32 linkCount
linkCount × {
    float startX, startY, startZ,
    float endX, endY, endZ,
    float radius,
    uint8 bidirectional,
    uint8 area
}

int32 gateCount
gateCount × {
    int32 gateId,
    float centerX, centerY, centerZ,
    float sizeX, sizeY, sizeZ,
    float rotationY,
    uint8 open
}
```

Agent 参数取场景第一个 `NavMeshSurface.agentTypeID` 的 `NavMeshBuildSettings`；多个 Surface 使用不同 agent 类型时只使用第一个并打印警告。

### 7.3 服务端加载

1. `NavMeshFileReader` 解析 `.rnav`（兼容 v1 无门、v2 含门）。
2. `NavMeshBuilder`：
   - 顶点按体素精度量化焊接；
   - 过滤退化三角形；
   - 建立共享边邻接；
   - 组装 `DtNavMeshCreateParams`。
3. `NavMeshWorld` 用 DotRecast `DtNavMeshQuery` 执行 `FindNearestPoly / FindPath / FindStraightPath`。
4. `DtNavMeshQuery` 不是线程安全的，所有查询和开关门操作都用锁串行化。
5. 出生点从世界坐标 `(0,0,0)` 找最近可行走点，搜索半径逐步扩大并排除关闭的门。

服务端启动参数（与地图/导航相关）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--navmesh` | `NavData/navmesh.rnav` | 导航数据路径 |
| `--mapdata` | `../Client/Assets/BundleRes/MapData/OpenWorld` | 地图数据目录（读取 `BuildingData.bytes`） |
| `--config` | `../Client/Assets/StreamingAssets/Config` | 配置表目录 |

`run.bat` 默认已传入 `--config` 和 `--mapdata`。

### 7.4 寻路请求与服务端校验

#### 7.4.1 客户端

`LocalPlayerController`：

1. 左键点击；如果关卡信息面板打开或点在 UI 上则忽略。
2. 射线检测：
   - 命中 `GateBuilding`：发送 `GateInfoReq` 打开关卡面板，**不寻路**；
   - 命中地面：目标点为命中点；
   - 未命中：用地形平面兜底。
3. 递增 `Seq`，发送 `PathFindReq { seq, target, clientPos }`。
4. 收到 `PathFindAck` 后：
   - `seq` 不匹配则丢弃；
   - 保存 `PathId / Speed / corners`；
   - 从 `start` 开始，沿拐点本地移动。

#### 7.4.2 服务端

`HandlePathFindAsync` 校验顺序：

1. 未登录 -> code 1。
2. `Target == null` -> code 2。
3. **起点使用服务端维护的玩家位置**，不信任 `clientPos`（`clientPos` 仅用于偏差检测/调试）。
4. `FindNearestPoly`：
   - 起点不在导航网格 -> 失败；
   - 终点不在导航网格 -> code 2。
5. `FindPath`：
   - 查询失败 / 无路径 -> code 3；
   - 部分路径（目标不可达）-> code 3。
6. `FindStraightPath` 生成拐点。
7. `PlayerEntity.SetPath`：`PathId++`，路径第一个点作为服务端吸附后的起点。
8. 返回 `PathFindAck { seq, code, pathId, corners, start, speed }`。

返回码：`0 成功、1 未登录、2 目标无效、3 不可达、4 服务器错误`。

#### 7.4.3 移动同步

- 服务端游戏循环 50ms 一 tick，玩家按 `Speed`（默认 4，限制 1~20）沿路径推进。
- 每 100ms 广播一次 `MoveSync { playerId, pathId, position, rotationY, moving, cornerIndex }`。
- 客户端本地预测移动：
  - 用 ack 的 `speed` 沿 `corners` 走；
  - 与 `MoveSync` 位置偏差超过 0.75m 时向服务端位置插值校正；
  - 收到 `moving=false` 且 `pathId` 相同 -> 停止并吸附到服务端位置。
- `SetMoveSpeedReq` -> 服务端校验并广播 `SetMoveSpeedSync`。

## 8. 关卡系统

系统里有两类“门”，用途不同：

| 类型 | 组件 | 数据来源 | 通行控制 |
|---|---|---|---|
| 全局关卡门 | `LevelGate` | `.rnav` v2 的 gate 列表 | 全局开关：门关闭时 poly flag=0，所有玩家都不可通行 |
| 地图建筑关卡 | `MapEntityInfo(Category=Building)` + 运行时 `GateBuilding` | `BuildingData.bytes` | 按玩家权限：服务端 `GateAccessMask` + `GateAccessFilter` |

> 全局门调试：`MazeGateDebugToggle` 按 `G` 请求切换场景里所有 `LevelGate`，服务端确认后广播 `GateStateSync`，客户端应用权威状态。

### 8.1 地图建筑关卡识别

- 服务端 `MapDataStore` 读取 `BuildingData.bytes`；
- 用 `MapBuildingCfg` + `MapBuildingTypeHelper.IsGate` 判断是否为关卡；
- 输出 `MapGateDefinition`：`InstanceId / ConfigId / Pos / Size / RotationY`。

### 8.2 关卡归属状态

| 状态 | 值 | 含义 |
|---|---|---|
| `None` | 0 | 无关系 |
| `Pending` | 1 | 已申请，待审批 |
| `Approved` | 2 | 已获得通行权 |
| `Rejected` | 3 | 申请被拒/通行权被移除 |
| `Owner` | 4 | 归属人 |
| `Unowned` | 5 | 无归属，当前禁止所有人通行 |

规则：

1. 无归属关卡禁止所有人通行，玩家可以「认领」，先到先得。
2. 归属人默认可通行。
3. 其他玩家可以申请；归属人审批后加入白名单。
4. 归属人可以移除白名单玩家；被移除者状态变为 `Rejected`，可以重新申请。
5. 只有归属人能查看申请列表和可通行列表；普通玩家只看到自己的状态。

### 8.3 关卡协议

| 消息 | 方向 | 说明 |
|---|---|---|
| `GateInfoReq { instanceId }` | C→S | 查询关卡信息 |
| `GateInfoAck` | S→C | 归属人、我的状态、白名单、申请列表 |
| `GateApplyReq { instanceId }` | C→S | 申请通行 |
| `GateApplyAck { instanceId, status, message }` | S→C | 申请结果 |
| `GateApproveReq { instanceId, playerId }` | C→S | 归属人同意 |
| `GateApproveAck` | S→C | 审批结果 |
| `GateRemoveAccessReq { instanceId, playerId }` | C→S | 归属人移除通行权 |
| `GateRemoveAccessAck` | S→C | 移除结果 |
| `GateClaimReq { instanceId }` | C→S | 认领无归属关卡 |
| `GateClaimAck` | S→C | 认领结果 |
| `GateAccessSync` | S→C | 权限变化后推送给归属人/被影响玩家 |

状态码见 8.2；`GateResultCode`：`0 成功、1 关卡不存在、2 不是关卡、3 不是归属人、4 状态非法、5 未登录、6 参数非法`。

### 8.4 服务端权限位图

`GateAccessStore`：

- 为每个关卡分配稳定 `GateIndex`；
- 每个玩家保存 `GateAccessMask`（`ulong[]` 位图）：
  - 归属人：对应位=1；
  - 白名单玩家：对应位=1；
  - 其他/无归属：0。
- 权限变化时 `RefreshAllGateMasks()`：
  - 重新构建所有**在线**玩家的位图；
  - 位图发生变化的玩家如果正在移动，调用 `PlayerEntity.Stop()` 停下（保留 `pathId`，客户端收到 `moving=false` 后停住）；
  - 推送一次 `MoveSync`。
- 离线玩家不保留位图；下次登录时重新 `BuildMask`。

当前为内存实现，服务器重启清空；正式环境应持久化，key 建议 `mapId + instanceId`。

### 8.5 导航多边形按玩家过滤

`NavMeshWorld`：

1. `RegisterMapGates` 遍历 `MapGateDefinition`：
   - 在关卡中心向上/向下探测地面高度；
   - 用旋转后的 AABB（高度 10m）调用 `QueryPolygons`；
   - 给覆盖到的 poly 加 `GatePolyFlag`，保留原有 `WalkableFlag` 与全局门状态；
   - 记录 `polyRef -> 该 poly 覆盖的 GateIndex 列表`。
2. 查询时：
   - 有 `GateAccessMask` 时使用 `GateAccessFilter`；
   - 普通 poly 直接通过；
   - 带 `GatePolyFlag` 的 poly，要求它关联的**所有** GateIndex 都在玩家位图中（多个门重叠时取交集）；
   - 任何一门未授权 -> 该 poly 不可走。
3. 全局 `LevelGate` 的开关仍通过 `SetPolyFlags` 修改 `WalkableFlag`，与建筑关卡的 `GatePolyFlag` 相互独立；开门时如果 poly 属于建筑关卡会恢复 `GatePolyFlag`。

效果：同一个导航网格，不同玩家查询到不同连通结果；无需为每个玩家拷贝导航网格。

### 8.6 客户端关卡 UI

`GateInfoPanel`（IMGUI，原型；后续可换 UGUI）：

- 点击关卡建筑 -> `GateInfoReq` -> 显示面板。
- 归属人：
  - 待审批申请列表，逐条「同意」；
  - 可通行玩家列表，逐条「移除」。
- 普通玩家：
  - 未归属：显示「认领关卡」；
  - 待审批：显示等待；
  - 已通过：显示已获得通行权；
  - 被拒绝/被移除：显示「申请通行」；
  - 无关系：显示「申请通行」。
- 面板打开时左键不触发寻路；Esc 或「关闭」隐藏。
- 权限变化通过 `GateAccessSync` 实时刷新面板。

### 8.7 点击关卡的交互

- `LocalPlayerController` 射线命中 `GateBuilding` 时请求关卡信息，不发送寻路请求。
- 流式加载的关卡建筑由 `MapDataStreaming` 在实例化时挂 `GateBuilding` 并写入 `InstanceId`。
- `GateBuilding.Initialize` 禁用 prefab 上可能存在的全局 `LevelGate` / `NavMeshObstacle`，避免与按玩家过滤冲突。

## 9. 障碍物、装饰物与导航

### 9.1 规则

| 类型 | 是否参与 NavMesh 烘焙 | 说明 |
|---|---|---|
| 装饰物 | 否 | 挂 `NavMeshModifier(ignoreFromBuild=true)` |
| 障碍物 | 是 | 不挂 `NavMeshModifier`，用来制造不可通行区域 |
| 建筑/采集资源 | 否（生成器统一处理） | 不应阻塞导航，门洞由关卡系统控制 |
| 墙体 | 是 | 归类为障碍物，`AssetPathCfg 301` |

### 9.2 编辑器行为

- 放置装饰物：立即挂 `NavMeshModifier` 并勾选 `Ignore From Build`。
- 放置障碍物：不挂任何导航组件。
- 导出装饰物：再兜底检查一次，确保手动拖入/复制的对象也带 `Ignore From Build`。
- 导出障碍物：不做忽略处理。

### 9.3 墙体

- 由 `RectMazeGenerator` 生成到 `DataEditor/Walls`，每个墙体单独一个 prefab 实例。
- 自动挂 `MapEntityInfo`：
  - `Category = Obstacle`
  - `ConfigId = AssetId = 301`（`AssetPathCfg 301 / Wall_1.prefab`）
  - `InstanceId` 留空，导出时生成。
- 生成器提供「给 Walls 墙体添加 MapEntityInfo (301)」按钮，用于已经手动改过场景、不想重新生成的情况。
- 导出时 `Walls` 节点并入 `ObstacleData`；因此导出时必须勾选 **Obstacle** 模块。
- 墙体不参与 `FlattenMapEntitiesAndAddModifiers` 的 Y=0 压平（pivot 在中心，需要保持 `WallY`）。

## 10. 端到端操作流程

### 10.1 首次搭建

1. 打开作者场景（如 `OpenWorld.unity`）。
2. `Tools/OpenWorld/Rect Maze Generator` 生成地形/围墙/关卡位置（可选烘焙）。
3. 打开 `Tools/Map Editor`：
   - 「创建/定位节点」确保 `DataEditor` 与四个分类根存在；
   - 放置建筑、装饰物、采集资源、障碍物；
   - 「补全/修复 UID」检查 InstanceId。
4. 场景资产整理：
   - MapEditor「整理当前场景资产」，或 Project 右键 `Assets/整理场景资产`。
5. 烘焙 NavMesh：
   - MapEditor「烘焙 NavMesh（当前场景）」。
6. 导出地图数据：
   - 勾选模块（至少包含需要导出的模块；墙体需要 **Obstacle**）；
   - 「导出客户端数据」「导出服务端数据」。
7. 导出导航数据：
   - MapEditor「导出 NavMesh (.rnav)」，覆盖 `Server/NavData/navmesh.rnav`。
8. 保存场景。
9. 重启 GameServer（加载新的 `navmesh.rnav` 和 `BuildingData.bytes`）。
10. 启动客户端，登录进入 Main 场景测试。

### 10.2 修改地图后

| 修改内容 | 需要重新执行 |
|---|---|
| 摆放/移动/删除建筑、装饰、资源、障碍 | 导出地图数据（对应模块） |
| 修改墙体或障碍物位置 | 重新烘焙 NavMesh + 导出 `.rnav` + 导出地图数据 + 重启服务器 |
| 只改装饰物 | 导出地图数据（Decorate）；不影响服务端寻路 |
| 改关卡归属逻辑/协议 | 重新编译服务器和客户端 |
| 改地形块 | 场景资产整理 + 重新导出地图/导航 + 重启 |

## 11. 关键实现注意点与已知限制

1. **起点以服务端为准**：`PathFindReq.clientPos` 只用于偏差检测，服务端寻路起点永远取 `PlayerEntity` 的位置。
2. **关卡权限是服务端权威**：客户端只发申请/审批请求，本地不修改通行状态；面板状态来自 `GateInfoAck / GateAccessSync`。
3. **无归属关卡默认禁止通行**：这是产品决策，避免未归属关卡变成公共通道；认领后才可管理。
4. **权限变化会打断移动**：`RefreshAllGateMasks` 会让正在移动的受影响玩家停下，避免角色继续穿过已失去权限的门。
5. **导航网格不按玩家复制**：通过 poly flag + 每玩家位图过滤，内存开销小；关卡数量增多时位图按 64 位分块扩展。
6. **地图关卡与全局门相互独立**：全局门控制 `WalkableFlag`，建筑关卡控制 `GatePolyFlag`；同一 poly 同时属于两者时，开门会保留建筑关卡标记。
7. **建筑类型历史值不一致**：`MapBuildingCfg.Type` 与 proto `BuildingType` 数值相反，必须通过 `MapBuildingTypeHelper` 判断，正式数据建议统一。
8. **InstanceId 必须唯一且持久化**：导出会补生成并写回，但需要保存场景；如果场景未保存就再次导出，会得到新的 Id。
9. **墙体依赖 Obstacle 模块导出**：只导出 Decorate 不会包含 Walls。
10. **场景资产整理是破坏性操作**：目标目录会被清空重建，源目录的贴图/材质/Mesh 会被移动；确认弹窗必须保留。
11. **运行时尺寸还原只支持 0/90/180/270 度**：任意角度旋转时保持 prefab 默认缩放，避免 AABB 投影导致拉伸错误。
12. **服务端只读取 BuildingData 和 .rnav**：Decorate/Resource/Obstacle 的 bytes 已导出，供后续系统使用；当前服务端不为它们建索引。
13. **地图数据模块可缺失**：客户端支持只导出部分模块；服务端地图加载失败会跳过并打印日志。
14. **关卡 poly 映射在服务端启动时计算**：修改关卡位置/尺寸后必须重新导出 `BuildingData.bytes` 并重启服务器。
15. **相机不跟随玩家**：地形块和地图实体都按相机地面投射框流式加载，缩放/拖动相机即可扩大加载范围。
