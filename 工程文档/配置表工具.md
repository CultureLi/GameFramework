# 配置表工具（Luban）改造说明

> 本文档对比 `GameFramework/ToolsSrc/luban` 与 luban 原版源码 `E:\Work\luban`（2025-06 快照），
> 列出全部源码差异，并说明每处差异的用途。
> 编译产物发布方式见 `ToolsSrc/luban/Readme.txt`：编译 `src/Luban` 后，把 `bin/Debug/net8.0` 下所有文件拷贝到仓库根目录的 `Tools/Luban`。

---

## 1. 改造目标

原版 luban 只能把配置表导出成散文件交给 Unity 打进 Bundle，多语言表是一整张表、大表一次性反序列化。本工程在此基础上做了四件事：

| 目标             | 解决的问题                                                | 关键差异                                                      |
| ---------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| 配置表独立热更   | 配置改动需要重打 Bundle，更新代价高                       | `CompressDataToZip` 打成 `configData.zip` + `configHash.hash` |
| 多语言按语言拆表 | 一张表带全部语言字段，包体和内存浪费，新增语言要改 schema | `--i18nTable` + `DataLoaderManager` 运行时拆表                |
| 大表懒加载       | 大表（如 Item/Resource 汇总）启动时全量反序列化，卡顿     | `--genOffsetTables` + `bin-offsetlength` + `cs-lazyload-bin`  |
| 代码裁剪         | 有些表只想导出数据、不想生成代码（多语言、语言列表）      | `--genCodeExclude`                                            |

## 3. 逐项说明

### 3.1 命令行与流水线

#### 3.1.1 `src/Luban/Program.cs`

新增三个参数：

```csharp
[Option("i18nTable")]        public string I18nTableName { get; set; }
[Option("genCodeExclude")]   public IEnumerable<string> GenCodeExclude { get; set; }
[Option("genOffsetTables")]  public IEnumerable<string> GenOffsetTables { get; set; }
```

**用途**：

- `--i18nTable I18nCfg`：告诉工具哪张表是多语言表，加载后按语言拆成多张表（见 3.3）。
- `--genOffsetTables ItemSummaryCfg ResourceSummaryCfg`：告诉工具哪些表要生成 offset 索引文件（见 3.4）。
- `--genCodeExclude I18nCfg LanguageCfg`：这些表不生成 C# 代码，因为多语言/语言列表的代码在 `Client/Assets/HotFixScripts/Framework/Localization` 里手写维护（固定 `Key/Value` 结构，不希望被 schema 生成覆盖）。

同时 `Main` 里加了一段本地调试代码：

```csharp
var debug = true;
if (debug) { customArgs = new string[] { ...硬编码 E:\Work\GameFramework 路径... }; }
```

**用途**：在 Visual Studio 里直接 F5 调试生成器，不用每次手写一长串参数；`--customTemplateDir` 也在这里指向 `Tools/Luban/Templates`。

> ⚠️ 该块目前 `debug = true`，会**覆盖真实命令行参数**。用 `DataTables/gen.bat` 或 `dotnet Tools/Luban/Luban.dll ...` 调用前必须改为 `false`（或删掉该块），否则永远生成到硬编码路径、并且模板目录也写死为 `E:\Work\GameFramework`。

#### 3.1.2 `PipelineArguments.cs`

新增 `I18nTableName` / `GenOffsetTables` / `GenCodeExclude` 三个属性，`Program.ParseArgs` 负责填充。**用途**：把命令行参数送进 `DefaultPipeline`，再下发给 `DefAssembly`。

#### 3.1.3 `DefaultPipeline.cs`

改动一：把三个参数传给 `DefAssembly`：

```csharp
_defAssembly = new DefAssembly(..., _args.GenOffsetTables);
_defAssembly.I18nTableName = _args.I18nTableName;
_defAssembly.GenCodeExclude = _args.GenCodeExclude;
_defAssembly.GenOffsetTables = _args.GenOffsetTables;
```

改动二：`ProcessTargets` 从“把所有 code target 塞进一个 Task 并行、所有 data target 并行”改为**逐个 target 顺序执行**（`Task.Run(...).Wait()`）。

**用途**：`bin` 与 `bin-offsetlength` 两个数据目标写同一个 `outputDataDir`，每个目标保存前都会清理目录；并行执行会互相删掉对方刚写出的文件。串行化后清理顺序确定。原版注释也写了 code target 本身不支持并行。

改动三：流水线最后新增 `CompressDataToZip()`（见 3.6.3）。

### 3.2 表模型基础改造

#### 3.2.1 `RawTable.PureName` + `DefaultTableImporter`

表定义来自文件名 `#I18nCfg.xlsx`：原版会生成表名 `TbI18nCfg`（`tableNameFormat = "Tb{0}"`）、值类型 `I18nCfg`。命令行参数里用户写的是**原始名** `I18nCfg`，原版模型里没有地方保存它，新增 `PureName` 保存 `I18nCfg`。

**用途**：`--i18nTable`、`--genOffsetTables`、`--genCodeExclude` 三个参数都按 `PureName` 匹配；同时拆分出的子表也继承 `PureName`，后续各环节仍能识别它们来自哪张原始表。

#### 3.2.2 `DefTable.cs`

| 差异                                                  | 用途                                                                                                                                               |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新增 `PureName`（普通构造与拷贝构造都赋值）           | 见上；拆分表继承原表 `PureName`                                                                                                                    |
| 新增 `public bool useOffset { get; set; }`            | 标记“这张表要懒加载”，由 `DefAssembly` 根据 `--genOffsetTables` 设置；代码目标/数据目标据此分流                                                    |
| 拷贝构造参数 `nameEx` → `name`                        | 语义统一：传入语言后缀（`cn`/`en`/…）                                                                                                              |
| 拷贝构造新增 `ValueType / ValueTType / Assembly` 赋值 | 原版拷贝构造遗漏了这几个字段，拆分表生成代码/数据时会拿到 null                                                                                     |
| 拷贝构造 `_outputFile = $"{b.Name}_{name}"`           | 原版复制 `b.OutputFile`，导致所有语言子表输出到**同一个文件名**互相覆盖；现在每语言一个文件（如 `TbI18nCfg_cn`）                                   |
| `OutputDataFile` 去掉 `.ToLower()`                    | 原版强制小写（`tb_i18ncfg_cn`），与运行时按 `typeof(T).Name`（`TbI18nCfg`）查找 zip entry 的大小写不一致；zip entry 名区分大小写，必须保留原大小写 |

#### 3.2.3 `DefAssembly.cs`

1. **构造参数新增 `genOffsetTables`**，构造表时：

```csharp
if (genOffsetTables.Contains(table.PureName)) { table.useOffset = true; }
```

**用途**：把“哪些表懒加载”变成配置项，而不是代码里写死。

2. **删除原版 i18n 特殊处理**：

```csharp
// 原版：任何 FullName 含 "i18n" 的表，复制一份同名加后缀的表
if (table.FullName.Contains("i18n")) { var table = new DefTable(table); ... }
```

原版这条逻辑会产生名字带随机后缀的重复表，且无法按语言拆分。本工程改为：**加载数据后**按语言拆分（见 3.3），所以构造阶段不再需要任何 i18n 特殊逻辑。

3. **新增 `RemoveTable` / `AddExportTable` / `RemoveType`**：i18n 拆分时需要先把原始整表从表集合、导出表集合、类型集合里摘掉，再逐个加入语言子表。

4. `GenCodeExclude` / `GenOffsetTables` / `I18nTableName` 三个属性挂在 `DefAssembly` 上，供代码目标读取。

#### 3.2.4 `GenerationContext.RemoveDataTable`

删除某表已加载的记录。配合 `DefAssembly.RemoveTable`，在 i18n 拆分时把整表数据从 `_recordsByTables` 移除，避免整表数据被导出或残留。

#### 3.2.5 `SchemaCollectorBase.Remove(RawTable)`

提供一个加锁的表移除接口。**当前全工程没有调用点**，属于改造过程中的残留/预留代码。

### 3.3 多语言表拆分（核心改动）

#### 3.3.1 `DataLoaderManager.cs`

表加载完成后：

```csharp
if (table.PureName.Equals(ctx.Assembly.I18nTableName))
{
    // 1) 把原始整表从 Assembly / GenerationContext 中移除
    // 2) 取主键字段之外的所有列名作为语言列表（cn / en / ja / ...）
    // 3) 每条记录 → 每种语言生成一条只含 (Key, 该语言Value) 的新记录
    // 4) 每种语言 new DefTable(table, 语言名)，注册成独立表并加入导出列表
}
else { ctx.AddDataTable(table, records, null); }
```

**用途**：配置表里 `I18nCfg` 是一张宽表（Key + 所有语言列），生成后变成 `TbI18nCfg_cn.bytes`、`TbI18nCfg_en.bytes`…… 每张都是窄表（Key + Value）。

带来的好处：

- 运行时只加载当前语言的表，内存和包体都省；
- 新增语言只加一列，不需要改任何运行时代码；
- 客户端代码 `I18nCfg` bean 固定为 `Key/Value` 两个字段（手写维护），与拆表结果完全对应。

配套：`ctx.Assembly.AddExportTable(newTable)` 是在 `ExportTables` 的同一 List 实例上追加，所以后续 code target / data target 遍历时能看到新表。

注意 `table.PureName.Equals(...)`：`PureName` 为 null 的表会 NRE。当前所有表都由文件名推导（`Datas/*.xlsx`），`PureName` 一定有值；如果以后改用 `__tables__.xlsx` 定义表，需要给 `RawTable` 补 `PureName`。

#### 3.3.2 `DBean.cs`

新增拷贝构造函数：

```csharp
public DBean(DBean other) { TType = ...; ImplType = ...; Fields = new List<DType>(); Fields.AddRange(other.Fields); }
```

**用途**：拆表时每条原始记录要复制出一份新的 `DBean`，再清空字段、只填当前语言的主键和值字段，避免破坏原始记录。

### 3.4 大表懒加载（offset）

整体链路：

```
配置表 --genOffsetTables--> useOffset=true
   ├─ cs-lazyload-bin  → TbXxxCfg.cs（继承 TableBase，UseOffset=true，按 key 取 offset/length 再反序列化）
   ├─ bin              → TbXxxCfg.bytes（纯数据，顺序排列）
   └─ bin-offsetlength → TbXxxCfg_offset.bytes（key, offset, length 索引）
```

#### 3.4.1 新增 `BinaryRecordOffsetLengthDataTarget`（`bin-offsetlength`）

原版只有 `bin-offset`：写 `key → offset`，且**没有长度**，运行时无法安全截取单条数据；也不区分表，所有表都会生成。

新目标：

```csharp
x.WriteSize(datas.Count);
foreach (d in datas) {
    // 每个索引字段的 key
    x.WriteSize(offset);   // 该记录在数据缓冲中的偏移
    x.WriteSize(length);   // 该记录长度
}
```

- `if (!table.useOffset) return null;` —— 只给登记过的表生成；
- 输出名 `{OutputDataFile}_offset.bytes`，与懒加载代码里的 `_offset.bytes` 对应；
- 缓冲初始 10KB（`new ByteBuf(10 * 1024)`），减少大表扩容拷贝。

**用途**：让运行时不必读完整表就能定位并反序列化单条记录（`ConfigMgr.OffsetByteBufLoader(file, offset, length)`）。

#### 3.4.2 `BinaryRecordOffsetDataTarget`（`bin-offset`）改造

同样加上 `useOffset` 判断，并把输出名改为 `_offset.bytes`（原版直接覆盖 `{OutputDataFile}.bytes`，会与 `bin` 目标输出打架）。

> 备注：`DataTables/gen.bat` 用的是 `-d bin bin-offsetlength`，`bin-offset` 目前未启用；这处改造是保持两套 offset 目标行为一致。

#### 3.4.3 `DataExporterBase.cs`

```csharp
var outputFile = dataTarget.ExportTable(...);
if (outputFile != null) manifest.AddFile(outputFile);
```

**用途**：数据目标可以通过返回 `null` 表示“这张表我不处理”（offset 目标据此跳过非懒加载表）。原版会 `AddFile(null)` 直接空引用。

#### 3.4.4 新增 `CsharpLazyLoadBinCodeTarget`（`cs-lazyload-bin`）

- 模板上下文压入 `CsharpBinTemplateExtension`（与 `cs-bin` 相同的序列化写法）；
- 只遍历 `ctx.ExportTables` 中 `useOffset == true` 且不在 `GenCodeExclude` 里的表；
- 不生成 bean / enum / Tables 管理器（bean 由 `cs-bin` 目标生成）。

**用途**：同一个 bean 类型，普通表和懒加载表需要两套 `Table` 模板，靠两个 code target 分工，避免在模板里写复杂分支。

#### 3.4.5 `TemplateCodeTargetBase.cs`

模板上下文新增 `{ "__useOffset", table.useOffset }`。

**用途**：`Tools/Luban/Templates/cs-bin/table.sbn` 等自定义模板可以按需生成 offset 相关成员。

### 3.5 代码生成裁剪与结构调整

#### 3.5.1 `CsharpCodeTargetBase.Handle` 重写

相对基类 `CodeTargetBase.Handle` 有两点变化：

1. 遍历表/bean 时跳过 `GenCodeExclude`：
    - 表按 `PureName` 匹配（`I18nCfg`、`LanguageCfg`）；
    - bean 按 `FullName` 匹配（本工程表都在 `Datas` 根目录、无命名空间，所以 `FullName` 就是 `LanguageCfg`，短名即可命中）。
2. **不再调用 `GenerateTables`**，即不生成 `Tables.cs` 管理器。

**用途**：

- 代码排除让“数据要导出、代码手写”的表（多语言表、语言列表）不被覆盖；
- 不生成管理器，是因为客户端改为运行时按需 `ConfigMgr.GetTable<T>()`（见第 4 节），不再需要一次性 new 出所有表、也不需要在管理器里硬编码全部表引用。

#### 3.5.2 `CsharpBinCodeTarget.Handle` 重写

在 `cs-bin` 目标上额外做三件事：

1. 跳过 `GenCodeExclude` 中的表；
2. 跳过 `--i18nTable` 指定的表（额外用 `I18nTableName.Contains(table.PureName)` 兜底，因为 `GenCodeExclude` 是按短名/全名分别匹配表和 bean 的）；
3. 跳过 `useOffset` 的表（这些表交给 `cs-lazyload-bin` 生成）。

bean / enum 仍然全部生成（同样支持 `GenCodeExclude`）。

**用途**：保证一张表只由**一个** code target 生成 `TbXxx.cs`，避免 `cs-bin` 与 `cs-lazyload-bin` 同时写出同名文件、后写覆盖先写。

### 3.6 输出清理与打包

#### 3.6.1 `LocalFileSaver.cs`

| 差异                                                                                  | 用途                                                                                                       |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `static HashSet<string> CleanDirs`，同一 `outputDir` 只清理一次                       | `bin` 和 `bin-offsetlength` 共用一个 `outputDataDir`，第二个目标保存前若再清理，会删掉第一个目标刚写的文件 |
| 清理开关键由 `outputSaver.<target>.cleanUpOutputDir` 改为 `<target>.cleanUpOutputDir` | 按 target 名读取；注意这会让旧写法 `outputSaver.*` 的配置失效                                              |
| 注释掉“删除整个目录再重建”的方案                                                      | 保留 `FileCleaner.Clean`（保留 `.meta`、删除不再生成的文件），避免 Unity 资产被整体重建                    |
| 增加 `ClearFolder` 日志                                                               | 便于排查“文件为什么没了”                                                                                   |

#### 3.6.2 `FileCleaner.cs`

仅把 `Directory.GetFiles(...)` 提取成局部变量 `files` 后再遍历，**行为不变**，属于改造过程中的中间状态。

#### 3.6.3 `DefaultPipeline.CompressDataToZip`

流水线最后一步（所有数据目标写完后）执行：

1. 删除旧的 `configData.zip` / `i18n.zip` / `configHash.hash`；
2. 递归取 `outputDataDir` 下所有 `*.bytes`，按路径排序（保证输出字节稳定）；
3. 文件名含 `I18n` 的进 `i18n.zip`，其余进 `configData.zip`；
4. 每个 zip entry 的 `LastWriteTime` 固定为 `2025-01-01 00:00:00 UTC`；
5. 对两个 zip 各算 SHA256，取前 4 字节转 8 位小写 hex；
6. 写 `configHash.hash`：

```json
{ "configData.zip": "1a782a72", "i18n.zip": "c95af44b" }
```

7. 删除所有中间 `*.bytes`。

**用途**：

- **配置热更**：客户端把 zip 和 hash 放到 `persistentDataPath/Config`，只比较 hash 决定是否下载，不走 Bundle（见 `DownloadConfigDataStage`）；
- **数据与多语言分离**：换语言或修文案只下 `i18n.zip`，改数值只下 `configData.zip`；
- **固定时间戳 + 排序**：同样的配置内容必须生成**完全相同**的 zip 字节，否则 hash 每次都变，客户端每次启动都白下载一遍；
- **删除 bytes**：`StreamingAssets/Config` 里只留 zip + hash，避免散文件和 zip 双份占用包体。

> ⚠️ 注意：
>
> - 分类依据是**文件名包含 `I18n`**，如果以后有非多语言表名里带 `I18n`，会被误打进 `i18n.zip`；
> - 清理 `*.bytes` 是**递归删除** `outputDataDir` 下全部 bytes，该目录只应作为配置表输出目录使用。

## 4. 运行时如何消费这些差异（客户端）

| 运行时位置                                             | 与本次改造的对应关系                                                                                                                         |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `Framework/Config/ConfigMgr.cs`                        | 打开 `configData.zip` / `i18n.zip`；`GetTable<T>()` 按 `UseOffset` 选择 `Initialize` 重载；`OffsetByteBufLoader` 按 offset+length 读单条记录 |
| `Framework/Config/TableBase.cs`                        | 懒加载表基类，`UseOffset` 默认 false，两个 `Initialize` 虚方法                                                                               |
| `GameEntry/Stage/DownloadConfigDataStage.cs`           | 下载 `configHash.hash`，逐 zip 比对 hash，只下载变化的 zip，解压到 `persistentDataPath/Config`                                               |
| `Framework/Localization/LocalizationMgr.cs`            | 按 `TbI18nCfg_{语言ISO}` 作为文件名取同一套 `TbI18nCfg` 代码，即 3.3 拆出的语言子表                                                          |
| `Framework/Localization/I18nCfg.cs` / `LanguageCfg.cs` | 手写的 `Key/Value` bean，对应 3.5.1 的 `--genCodeExclude`                                                                                    |
| `GameMain/Config/Gen/TbItemSummaryCfg.cs` 等           | 由 `cs-lazyload-bin` 生成，`UseOffset => true`，读 `_offset.bytes`                                                                           |

## 5. 与 `Tools/Luban/Templates` 的关系

`ToolsSrc/luban` 只负责生成器逻辑，代码模板由 `--customTemplateDir` 提供（当前指向 `Tools/Luban/Templates`），两者必须配套：

- `cs-bin/table.sbn`：表基类改为 `Framework.TableBase`，`Initialize(name, streamLoader)`；
- `cs-bin/tables.sbn`、`cs-lazyload-bin/tables.sbn`（Tables 管理器模板）：仍然保留在模板目录里，但因为两个 code target 的 `Handle` 都不再调用 `GenerateTables`，**实际不会被生成**；`cs-bin/table.sbn` 里也没有 `ResolveRef` 方法，若哪天恢复生成管理器会编译失败，需要一并处理；
- `cs-lazyload-bin/`：`TableBase` + `UseOffset` + `_offset.bytes` + 按 key 懒加载；
- `common/cs/`：只保留 `enum.sbn`，其余语言目录多余但对 C# 目标无影响。

所以：**升级 `ToolsSrc/luban` 源码后，必须重新编译并把产物拷到 `Tools/Luban`，同时确认模板目录同步**，否则会出现“生成器支持 offset、模板却不认识 `__useOffset`”之类的不匹配。

## 6. 注意事项与遗留问题

1. **`Program.cs` 的 `debug = true` 硬编码参数块**：会覆盖命令行参数，且路径写死为 `E:\Work\GameFramework`。发布前必须关闭；同时它与 `DataTables/gen.bat` 是两份参数，改动时要同步。
2. **空值风险**：
    - `DataLoaderManager` 里的 `table.PureName.Equals(...)`：`PureName` 为 null 会 NRE（仅当表改由 `__tables__.xlsx` 定义时出现）；
    - `CsharpBinCodeTarget` 里的 `ctx.Assembly.I18nTableName.Contains(...)`：不传 `--i18nTable` 时 NRE；
    - `DefAssembly` 构造参数 `genOffsetTables` 默认 `null`：不通过 `DefaultPipeline` 构造时 `Contains` 会 NRE。
3. **未使用/冗余代码**：`SchemaCollectorBase.Remove(RawTable)` 无调用点；`DefAssembly` 构造后又被赋值一次 `GenOffsetTables`；`Program.cs` 多了两个未使用的 `using`；`bin-offset` 目标已改造但 `gen.bat` 未启用。
4. **打包分类靠文件名**：`file.Contains("I18n")` 属于字符串匹配，表命名需要遵守约定。
5. **`--genCodeExclude` 的匹配口径不统一**：表用 `PureName`（短名），bean 用 `FullName`。当前表都在 `Datas` 根目录、无命名空间，短名刚好等于 `FullName`；一旦把表放到子目录（产生命名空间），bean 的排除就会失效。
6. **`LocalFileSaver` 清理开关键变化**：旧配置文件里 `outputSaver.<target>.cleanUpOutputDir` 不再生效。
