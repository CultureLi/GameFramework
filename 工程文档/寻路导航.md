# 寻路导航系统（需求与实现）

> 本文档整理当前客户端/服务端的寻路与导航实现，包括：数据来源、依赖库、烘焙与导出流程、联机/单机寻路、关卡通行规则、协议和已知限制。

---

## 1. 目标

1. 客户端支持 **联机** 与 **单机** 两种模式。
2. 联机模式：寻路由服务器权威计算，客户端只做输入、表现和位置校正。
3. 单机模式：客户端直接使用同一套 Recast/DotRecast 数据本地寻路，不连接服务器。
4. 关卡建筑支持归属、认领、申请、审批、移除通行权；不同玩家得到不同寻路结果。
5. 客户端与服务端使用同一份 Unity 导出的导航数据，保证路径一致。

---

## 2. 总体架构

### 2.1 联机模式

```
玩家点击地面
  -> Client: PathFindReq { seq, target, clientPos }
  -> Server: 以服务端维护的玩家位置为起点
  -> DotRecast: FindNearestPoly / FindPath / FindStraightPath
  -> Server: PathFindAck { pathId, corners, start, speed }
  -> Client: 沿 corners 本地预测移动
  -> Server: 50ms tick 推进，100ms 广播 MoveSync
  -> Client: 偏差超过阈值时向服务端位置校正
```

关卡点击：

```
Client 射线命中 GateBuilding
  -> GateInfoReq(instanceId)
  -> Server 返回 GateInfoAck
  -> 客户端打开 GateInfoPanel
```

### 2.2 单机模式

```
UIGameEntryLogin 选择“单机” -> 跳过登录 -> 进入 Main
  -> PathfindingMgr 创建 LocalPathfindingService
  -> 通过 Addressables 加载 navmesh.bytes
  -> MapDataMgr 加载 BuildingData 后注册建筑关卡
  -> 玩家点击地面 -> LocalPathfindingService.FindPath
  -> 客户端沿 corners 本地移动（无 MoveSync）
```

## 4. 数据来源

### 4.1 导航网格从哪里来

1. 在 Unity 场景中使用 `NavMeshSurface` 烘焙。
2. 烘焙对象主要是地形、墙体、障碍物等静态几何。
3. 关卡门在烘焙时先临时打开（禁用 `LevelGate` 的碰撞体 / `NavMeshObstacle`），让门洞在静态导航网格里是可通行的。
4. 烘焙参数：
   - `CollectObjects.All`
   - `Use Geometry = Physics Colliders`
   - `Ignore NavMesh Agent = true`
   - `Ignore NavMesh Obstacle = true`
   - `AgentTypeID = 0`
   - Surface 的 Transform 归零，避免整体偏移。
5. 烘焙完成后由 `NavMeshExporter` 调用 `NavMesh.CalculateTriangulation()` 导出。

### 4.2 导航数据文件 `.rnav`

`NavMeshExporter` 导出 v2 格式：

```text
char[4]  magic = "RNAV"
uint32   version = 2

float agentHeight
float agentRadius
float agentClimb
float cellSize
float cellHeight

int32 vertexCount
vertexCount × (float x, float y, float z)

int32 triangleCount
triangleCount × 3 × int32 indices
triangleCount × uint8 area

int32 linkCount
linkCount × {
    float startX, startY, startZ,
    float endX, endY, endZ,
    float radius,
    uint8 bidirectional,
    uint8 area
}

int32 gateCount
gateCount × {
    int32 gateId,
    float centerX, centerY, centerZ,
    float sizeX, sizeY, sizeZ,
    float rotationY,
    uint8 open
}
```

- 三角形来自 Unity 已烘焙的 NavMesh。
- Link 来自场景中的 `NavMeshLink`。
- gate 段来自全局 `LevelGate`，供服务端做全局开关。
- **地图建筑关卡**不在这段 gate 数据里，而是从 `BuildingData` 读取。

### 4.3 地图建筑关卡数据

地图编辑器把关卡作为建筑摆放并导出：

- 客户端：`Assets/AssetBundles/MapData/<SceneName>/BuildingData.asset`
- 服务端：`Server/MapData/<SceneName>/BuildingData.bytes`

每条 `MapItemData`/`MapBinaryEntry`：

```text
string instanceId
int    id            // MapBuildingCfg.Id
float  posX, posZ
float  sizeX, sizeZ
float  rotationY
```

服务端 `MapDataStore` 读取 `BuildingData.bytes`，再用：

- `MapBuildingCfg`
- `AssetPathCfg`
- `MapBuildingTypeHelper.IsGate`

筛出关卡建筑，生成 `MapGateDefinition`。

### 4.4 当前导出目录

| 数据 | 客户端 | 服务端 |
|---|---|---|
| 地图 SO/bytes | `Assets/AssetBundles/MapData/<SceneName>/` | `Server/MapData/<SceneName>/` |
| 导航数据 | `Assets/AssetBundles/MapData/<SceneName>/navmesh.bytes` | `Server/MapData/<SceneName>/navmesh.rnav` |

兼容旧路径（导出时也会同步一份）：

- `Assets/Resources/NavData/navmesh.bytes`
- `Server/NavData/navmesh.rnav`

客户端单机寻路优先读 Addressables 的新地址，找不到时回退 `Resources/NavData/navmesh.bytes`。

### 4.5 Addressables

- 客户端导航文件 `navmesh.bytes` 由 `NavMeshExporter` 注册到 `MapData` 组。
- 地图 SO（BuildingData 等）由 `MapDataExporter` 注册到 `MapData` 组。
- AutoGroup 工具也为 `AssetBundles/MapData` 增加了 `.bytes` 规则，重新分组时不会漏掉 navmesh。
- 地图场景（Main/OpenWorld）通过 Addressables 场景加载。

### 4.6 配置表

| 表 | 用途 |
|---|---|
| `MapBuildingCfg` | 建筑 Id、AssetId、Name、Type（关卡/普通建筑） |
| `AssetPathCfg` | 建筑/装饰/障碍物实际 prefab 路径 |
| `MapResourceCfg` | 采集资源配置 |

`MapBuildingTypeHelper` 兼容历史数据：

- 当前数据里 `Type=1` 表示关卡；
- proto `BuildingType.Gate=2`；
- 判断时同时看资源路径/名称是否包含 `Gate`/`关卡`。

## 5. 烘焙与导出流程

1. 打开作者场景（默认 `OpenWorld`）。
2. 生成/调整地形、围墙、关卡位置。
3. 使用 `NavMeshSurface` 烘焙。
4. 在 MapEditor 里点击「导出 NavMesh」：
   - `NavMeshExporter` 生成 `.rnav`；
   - 服务端写到 `Server/MapData/<SceneName>/navmesh.rnav`；
   - 客户端同步 `Assets/AssetBundles/MapData/<SceneName>/navmesh.bytes`；
   - 注册到 Addressables `MapData` 组；
   - 兼容路径也写一份。
5. 在地图编辑器导出地图数据：
   - 客户端 `BuildingData.asset` 等；
   - 服务端 `BuildingData.bytes` 等。
6. 重启 GameServer 加载新的 navmesh / BuildingData。

> 修改地形、墙体、障碍物、关卡位置后，必须重新烘焙并导出 `.rnav`，并重启服务器。

## 6. 服务端寻路

### 6.1 加载

`NavMeshWorld.Load(path)`：

1. `NavMeshFileReader` 解析 `.rnav`。
2. `NavMeshBuilder` 将三角形组装成 Detour 导航网格：
   - 顶点按体素精度量化并焊接，修复 tile 接缝处索引不共享；
   - 过滤退化三角形；
   - 建立共享边邻接；
   - 组装 `DtNavMeshCreateParams`；
   - `DtNavMeshBuilder.CreateNavMeshData` + `DtNavMesh.Init`。
3. 注册 `.rnav` 中的全局关卡门。
4. 从世界坐标 `(0,0,0)` 用 `FindNearestPoly` 搜索出生点。

### 6.2 查询

`FindPath`：

1. `FindNearestPoly` 吸附起点/终点；
2. `FindPath` 计算多边形路径；
3. `IsPartial()` 视为「目标不可达」；
4. `FindStraightPath` 生成拐点；
5. 返回 `List<RcVec3f> corners`。

### 6.3 移动

- `PlayerEntity` 保存服务端位置、路径、路径索引、速度、`PathId`。
- 游戏循环每 50ms tick，按速度沿路径推进。
- 每 100ms 广播 `MoveSync`。
- 默认速度 4，限制 1~20。

### 6.4 服务端配置

默认场景 `OpenWorld`：

```text
MapData/<SceneName>
MapData/<SceneName>/navmesh.rnav
```

启动参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--scene` | `OpenWorld` | 场景名，决定 MapData 目录 |
| `--mapdata` | `MapData/<SceneName>` | 地图数据目录 |
| `--navmesh` | `MapData/<SceneName>/navmesh.rnav` | 导航数据 |
| `--config` | `../Client/Assets/StreamingAssets/Config` | 配置表 |

`run.bat` 默认只传 `--config` 和 `--scene OpenWorld`，路径由服务端按场景推导。

服务端启动会打印：

```text
[server] 场景=OpenWorld 地图数据=...\Server\MapData\OpenWorld 导航数据=...\Server\MapData\OpenWorld\navmesh.rnav
```

## 7. 客户端联机寻路

### 7.1 入口

- `UIGameEntryLogin` 下拉框选择模式：
  - 单机：`GameModeSettings.Mode = SinglePlayer`
  - 联机：`GameModeSettings.Mode = Online`
- 联机模式点击登录后走原有 `LoginSession` 网络登录。

### 7.2 点击与寻路

`LocalPlayerController.HandleClick`：

1. 射线检测：
   - 命中 `GateBuilding` → `PathfindingMgr.RequestGateInfo(instanceId)`，不寻路；
   - 命中地面 → 目标点；
   - 未命中地形 → 用地面平面兜底。
2. 发送 `PathFindReq { seq, target, clientPos }`。
3. 收到 `PathFindAck`：
   - `seq` 不匹配丢弃；
   - 保存 `pathId / speed / corners / start`；
   - 从 `start` 开始沿拐点本地移动；
   - 显示行军线。
4. `MoveSync`：
   - `moving=false` 且 `pathId` 相同 → 停止、吸附；
   - 位置偏差超过 0.75m → 向服务端位置插值校正。

### 7.3 行军线

`MarchLine`（Prefab `TroopMarchLineWorld`）：

- 沿路径生成 Mesh；
- UV 的 V 沿路径长度铺开；
- `MarchLineView.shader` 用 `_SpeedV` 滚动 UV，形成虚线/箭头向前流动；
- 起点每帧跟随角色；
- 到达终点或服务端停止移动后隐藏。

## 8. 客户端单机寻路

### 8.1 模式选择

- 默认单机。
- `UIGameEntryLogin.OnBtnLoginClick` 在单机模式下跳过账号校验和 `LoginSession`，直接 `EnterGameMain()`。
- 单机模式禁用账号/密码输入框，隐藏「启动服务器」按钮。

### 8.2 初始化

`PathfindingMgr.Initialize`：

1. `GameModeSettings.IsSinglePlayer == true` 时创建 `LocalPathfindingService`；
2. `ResolveMapName()` 取 `WorldChunkStreaming.sceneName`，否则当前场景名；
3. `LocalPathfindingService` 从：
   - `Assets/AssetBundles/MapData/<SceneName>/navmesh.bytes`（Addressables）
   - 失败时回退 `Resources/NavData/navmesh.bytes`
4. 解析 `.rnav` 并构建 Detour 网格；
5. 玩家出生点使用导航网格吸附点。

### 8.3 关卡注册

`MapDataMgr` 加载完 `BuildingData.asset` 后：

```text
PathfindingMgr.I.SetLocalBuildingData(buildingData)
  -> LocalPathfindingService.SetBuildingData
  -> 筛选 BuildingType=Gate
  -> new GateAccessStore(definitions)
  -> NavMeshWorld.RegisterMapGates(definitions)
```

### 8.4 本地寻路

点击地面：

```text
PathfindingMgr.RequestLocalPath(target)
  -> LocalPathfindingService.FindPath(player.FeetPosition, target)
  -> NavMeshWorld.FindPath(..., CurrentMask)
  -> player.ApplyLocalPath(corners)
```

- 不发送 `PathFindReq`，不等待 `MoveSync`。
- 本地沿 corners 移动。
- 关卡权限使用本地 `GateAccessStore`，逻辑与服务端一致。

> 如果 `BuildingData` 尚未加载完成，单机寻路会暂时不检查关卡权限，并在控制台打印警告；加载完成后恢复正常。

## 9. 关卡通行规则

### 9.1 两类关卡门

| 类型 | 组件 | 数据来源 | 通行控制 |
|---|---|---|---|
| 全局关卡门 | `LevelGate` | `.rnav` v2 gate 列表 | 全局开关，关闭时所有玩家都不可走 |
| 地图建筑关卡 | 建筑 + 运行时 `GateBuilding` | `BuildingData` | 按玩家权限过滤导航多边形 |

### 9.2 地图建筑关卡识别

服务端 `MapDataStore`：

1. 读取 `BuildingData.bytes`；
2. `MapBuildingCfg` + `MapBuildingTypeHelper.IsGate` 判断；
3. 输出 `MapGateDefinition`：
   - `InstanceId`
   - `ConfigId`
   - `PosX/PosZ`
   - `SizeX/SizeZ`
   - `RotationY`
4. `GateAccessStore` 为每个关卡分配稳定 `GateIndex`。

### 9.3 玩家状态

| 状态 | 值 | 含义 |
|---|---|---|
| `None` | 0 | 无关系 |
| `Pending` | 1 | 已申请，待审批 |
| `Approved` | 2 | 已获得通行权 |
| `Rejected` | 3 | 申请被拒 / 通行权被移除 |
| `Owner` | 4 | 归属人 |
| `Unowned` | 5 | 无归属，当前禁止所有人通行 |

### 9.4 通行规则

1. **未归属关卡禁止所有人通行**。
2. 玩家可以认领无归属关卡，先到先得。
3. 归属人默认可通行。
4. 其他玩家可以申请，归属人审批后加入白名单。
5. 归属人可以移除白名单玩家；被移除者变为 `Rejected`，可以重新申请。
6. 只有归属人能查看申请列表和可通行列表。
7. 权限变化后，在线玩家重新构建位图；正在移动的受影响玩家停止移动（保留 `pathId`，客户端收到 `moving=false` 后停住）。
8. 离线玩家不保留位图，下次登录时重新 `BuildMask`。

### 9.5 每玩家通行位图

`GateAccessMask`：

- `ulong[]` 位图；
- 每个关卡一个 bit；
- `Owner` 或 `Approved` 玩家对应 bit = 1；
- 未归属 / 其他玩家 = 0。

`BuildMask(playerId)` 在以下时机重建：

- 登录成功；
- 认领 / 申请通过 / 移除通行权；
- 其他归属系统调用 `SetOwner`。

### 9.6 导航多边形过滤

`NavMeshWorld.RegisterMapGates`：

1. 在关卡中心向上/向下找地面高度；
2. 用旋转后的关卡 AABB（高度 10m）`QueryPolygons`；
3. 给覆盖到的 poly 加 `GatePolyFlag`，保留原有 `WalkableFlag` 和全局门状态；
4. 记录 `polyRef -> GateIndex 列表`。

`GateAccessFilter`：

1. 先通过基础过滤器（`WalkableFlag | GatePolyFlag`）；
2. 非关卡 poly 直接通过；
3. 关卡 poly 要求其关联的**所有** GateIndex 都在玩家位图中；
4. 多个关卡重叠时取交集：任何一个门未授权，该 poly 不可走。

### 9.7 全局门

- 全局 `LevelGate` 控制 `WalkableFlag`；
- 地图建筑关卡控制 `GatePolyFlag`；
- 两者独立；
- 全局门打开时，如果该 poly 也属于地图关卡，会恢复 `GatePolyFlag`。

### 9.8 客户端关卡 UI

`GateInfoPanel`：

- 点击关卡 → `GateInfoReq` / 本地 `GetGateInfo`；
- 归属人：待审批列表 + 可通行列表，可同意/移除；
- 普通玩家：
  - 未归属：显示「认领关卡」；
  - 待审批：等待；
  - 已通过：已获得通行权；
  - 被拒绝/被移除：申请通行；
  - 无关系：申请通行。
- 面板打开时左键不触发寻路。

## 10. 协议

### 10.1 寻路/移动

| 消息 | 方向 | 字段 |
|---|---|---|
| `PathFindReq` | C→S | `seq, target, clientPos` |
| `PathFindAck` | S→C | `seq, code, message, pathId, corners[], start, speed` |
| `MoveSync` | S→C | `playerId, pathId, position, rotationY, moving, cornerIndex` |
| `SetMoveSpeedReq` | C→S | `speed` |
| `SetMoveSpeedSync` | S→C | `playerId, speed, code` |

寻路返回码：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 未登录 |
| 2 | 目标无效 |
| 3 | 不可达 |
| 4 | 服务器错误 |

### 10.2 关卡

| 消息 | 方向 |
|---|---|
| `GateInfoReq / GateInfoAck` | C→S / S→C |
| `GateApplyReq / GateApplyAck` | C→S / S→C |
| `GateApproveReq / GateApproveAck` | C→S / S→C |
| `GateRemoveAccessReq / GateRemoveAccessAck` | C→S / S→C |
| `GateClaimReq / GateClaimAck` | C→S / S→C |
| `GateAccessSync` | S→C |

`GateResultCode`：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 关卡不存在 |
| 2 | 不是关卡 |
| 3 | 不是归属人 |
| 4 | 状态非法 |
| 5 | 未登录 |
| 6 | 参数非法 |

## 12. 验证与测试要点

1. 服务端启动日志应显示从 `MapData/<SceneName>/navmesh.rnav` 加载。
2. 服务端应打印关卡建筑数量和每个关卡覆盖的 poly 数量。
3. 未认领关卡另一侧的目标点应返回「目标不可达」。
4. 点击关卡 → 认领 → 再次寻路应可通行。
5. 其他玩家未获授权时不可通行；归属人同意后可通行；移除后恢复不可通行。
6. 联机模式：
   - 点击地面收到 `PathFindAck`；
   - 行军线出现并跟随角色；
   - `MoveSync` 校正位置；
   - 切换关卡权限后正在移动的角色会停下。
7. 单机模式：
   - 不产生 TCP 连接；
   - 从 Addressables 新路径加载 navmesh；
   - 本地寻路和关卡认领可用；
   - 若新 navmesh 未注册，能回退 Resources 旧路径。
8. 客户端与服务端使用的 `.rnav` 应一致（可比较文件 MD5）。
9. 可用 `Server/Tools/NavMeshViewer` 可视化导航网格、关卡覆盖和连通性。

## 13. 已知限制与注意事项

1. **单机关卡数据延迟**：`BuildingData` 还未加载完成时，单机寻路暂不检查关卡权限，控制台会打印警告。
2. **导航数据必须同步**：客户端单机和服务端联机使用同一份 Unity 导出的 `.rnav`；重新烘焙后两端都要更新。
3. **关卡位置/尺寸变化**：必须重新导出 `BuildingData` 并重启服务端，因为关卡 poly 映射在启动时计算。
4. **全局门与建筑关卡独立**：`LevelGate` 控制全局可走性，建筑关卡控制玩家权限；不要混用。
5. **位图为会话内缓存**：服务端当前为内存实现，重启后归属/白名单清空；正式服应持久化（mapId + instanceId）。
6. **建筑类型枚举历史值**：`MapBuildingCfg.Type` 与 proto `BuildingType` 数值相反，依赖 `MapBuildingTypeHelper` 兼容。
7. **客户端 DotRecast 为 DLL**：源码不在工程内，来自 NuGet `2026.3.1`；需要修改 DotRecast 时必须从源码构建并替换 DLL，同时注意 `link.xml` 保留。
8. **HybridCLR/AOT 裁剪**：DotRecast 类型通过 `link.xml` 保留；新增泛型使用时可能需要重新生成 AOT 元数据。
9. **单机模式默认无网络**：`UIGameEntryLogin` 单机分支不会初始化 `FW.NetMgr`；联机相关 UI/按钮在单机下隐藏或禁用。
10. **服务端默认场景 OpenWorld**：可通过 `--scene` 切换；`--mapdata` / `--navmesh` 可显式覆盖。
